# Гарантийный отдел

## Реализовано

- отдельное Django-приложение `warranty`;
- доступ к веб-разделу только для системного администратора;
- идемпотентный импорт обращений, истории и файлов из Bitrix;
- хранение полного исходного снимка каждой записи для аудита и повторной обработки;
- поиск, фильтр по статусу, карточка клиента и изделия;
- ответственный, приоритет, срок решения, комментарий;
- история изменений, вложения, работы, диагностика и запчасти;
- модель Telegram-обсуждения и локальная история сообщений;
- архивирование обсуждения при закрытии и восстановление при повторном открытии.

## Почему Telegram-тема, а не отдельная удаляемая группа

Telegram Bot API не даёт надёжного сценария «удалить группу, а потом восстановить её вместе с перепиской». Удаление темы также уничтожает сообщения. Поэтому целевая схема — закрытая супергруппа гарантийного отдела в режиме форума и отдельная тема на каждое обращение:

1. новое обращение создаёт тему;
2. бот публикует карточку и закрепляет её;
3. входящие сообщения и файлы зеркалируются в БД;
4. закрытие обращения вызывает `closeForumTopic`;
5. повторное открытие вызывает `reopenForumTopic`, история остаётся на месте.

## Результаты анализа рынка

В модель заложены общие возможности профильных систем:

- Odoo Repairs: связка обращения и ремонтного заказа, серийный номер, гарантийный признак, ответственный, запчасти, резервирование, ремонтные этапы, возврат клиенту и платный ремонт;
- Zoho Desk: приоритеты, каналы поступления, категории, SLA, сроки, эскалации, вложения и статусы ожидания;
- сервисные helpdesk/repair-системы: единая временная шкала, назначение исполнителей, диагностика, смета, складские позиции, документы и уведомления.

Источники:

- https://www.odoo.com/documentation/17.0/applications/services/helpdesk/advanced/after_sales.html
- https://www.odoo.com/documentation/17.0/applications/inventory_and_mrp/repairs/repair_orders.html

- https://help.zoho.com/portal/en/kb/desk/automation/escalate-sla/articles/understanding-and-working-with-slas

3. Реализовать создание/закрытие/повторное открытие тем через очередь.
4. Добавить SLA, рабочий календарь и эскалации.
5. Добавить склад запчастей, резервирование и движение остатков.
6. Добавить шаблоны актов, заключений, смет и уведомлений клиенту.
7. После стабилизации выдать отдельные роли сотрудникам гарантийного отдела и сервисного центра.

## Импорт

Экспортёр `warranty/bitrix_readonly_export.php` выполняет только `SELECT`. Импорт запускается командой:

```bash
python manage.py import_bitrix_warranty export.json --files-root /path/to/files
```

Повторный запуск безопасен: обращения сопоставляются по `(source, external_id)`, история и файлы — по внешним ID.
