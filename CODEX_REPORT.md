## 6. Важные архитектурные решения

- `config` используется только как пакет конфигурации проекта; предметная
  логика должна размещаться в приложениях, начиная с `checklists`.
- Настройки `SECRET_KEY`, `DEBUG` и `ALLOWED_HOSTS` читаются через
  python-dotenv. `.env.example` отслеживается, реальный `.env` игнорируется.
- Для локальной разработки по умолчанию используется SQLite.
- При `DATABASE_ENGINE=postgresql` настройки переключаются на PostgreSQL и
  читают параметры `POSTGRES_*`; драйвер psycopg уже установлен.
- Прямые зависимости закреплены точными версиями в `requirements.txt`.
- Для тестов выбран pytest-django; текущий тест проверяет только корректную
  регистрацию приложения.
- Gunicorn подготовлен как production WSGI-сервер.
- Bootstrap 5 запланирован для интерфейса, но шаблоны и фронтенд на этом этапе
  намеренно не создавались.
- Предметные модели, пользовательские роли и интерфейс пока отсутствуют.
