# Передача контекста: уведомление о невыполненных пунктах

## Где находится проект

- Сервер: хост Termius `Checklist`, пользователь `autobud_checklist`.
- Рабочая директория: `/home/a/autobud/checklist/public_html/django_app`.
- Приложение: Django, основной модуль `checklists`.
- Рабочий адрес: `https://checklist.es-helper.ru/`.
- На сервере нет Git-репозитория; исходники были скопированы на Mac 1 августа 2026 года.

## Запрошенное поведение

При закрытии этапа/периода, если сотрудник отметил пункт как «Не выполнено», в рабочий Telegram-чат должно прийти сообщение, содержащее:

1. название магазина, сотрудника и этапа;
2. каждый оставшийся невыполненным пункт;
3. комментарий менеджера/сотрудника к каждому такому пункту;
4. явную подсказку другим сотрудникам взять задачу в работу на следующий день.

Сообщение должно отправляться при закрытии этапа независимо от того, закрыт он вовремя или с опозданием. Повторное закрытие не должно создавать дубликаты.

## Что уже установлено по коду

- Статус «Не выполнено»: `ChecklistAnswer.Status.FAILED` в `checklists/models.py`.
- Комментарий хранится в `ChecklistAnswer.comment`.
- Форма в `checklists/forms.py` уже требует непустой комментарий при `FAILED` (если для пункта включено соответствующее требование).
- Снимок текста пункта хранится в `DailyChecklistItem.item_text`.
- Закрытие этапа выполняет `complete_checklist_stage()` в `checklists/services.py`.
- Сейчас эта функция создаёт Telegram-уведомление только для этапа, закрытого с опозданием: `create_completed_late_notification()`.
- Уведомления реализованы через `ChecklistNotification` и `checklists/notifications.py`.
- Доступные типы: `deadline_warning`, `overdue`, `completed_late`.
- Текст формируется в `build_notification_text()`.
- Рабочий чат берётся из `StoreNotificationSettings.telegram_chat_id`.
- Защита от дублей уже обеспечивается ограничением `UniqueConstraint(stage, notification_type)`.
- Настройка итоговых уведомлений магазина: `completed_late_enabled`; её разумно переиспользовать для нового уведомления о проблемах либо добавить отдельный флаг в интерфейс настроек.

## Предлагаемая реализация

1. Добавить тип `ChecklistNotification.NotificationType.COMPLETED_WITH_ISSUES`.
2. Добавить `create_completed_with_issues_notification(stage)`, которая создаёт запись только если в закрываемом этапе есть ответы `FAILED`.
3. Вызывать её из `complete_checklist_stage()` после сохранения закрытого этапа — и для своевременного, и для позднего закрытия.
4. В `build_notification_text()` получить ответы этапа со статусом `FAILED`, отсортировать по порядку пунктов, HTML-экранировать `item_text` и `comment`, затем сформировать список.
5. Доставлять через существующую очередь и тот же рабочий `telegram_chat_id`.
6. Добавить миграцию выбора типа уведомления и тесты: создание только при `FAILED`, отсутствие дублей, наличие текста и комментария, HTML-экранирование, отправка вовремя и с опозданием.

## Важные ограничения

- Не хранить в Git `.env`, `store-checklist.env`, базы, SQL-дампы, архивы и резервные файлы.
- Перед серверными изменениями сделать резервную копию кода и БД.
- После развертывания применить миграции, выполнить Django system check и профильные тесты уведомлений/закрытия этапов.
